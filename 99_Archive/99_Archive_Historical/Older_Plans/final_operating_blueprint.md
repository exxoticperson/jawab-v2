- **Gulf-native signal:** Arabic name tells Gulf clinic owners "this was built *for* you" — not translated from English SaaS

- **Tagline writes itself:** *"Every call deserves a Jawab"* / *"Your clinic's Jawab"*
- **Domain-friendly:** jawab.io, getjawab.com, jawab.health
- **Differentiates instantly** from generic English-named competitors (Arini, Dentina.ai)

**Brand line:** `Jawab — No call goes unanswered.`

## 4 · PRODUCT & SYSTEM LAYER

### 4.1 · V1 Core Flow

```
Missed Call
    ↓
[Trigger: Twilio detects unanswered call]
    ↓
Instant WhatsApp Message (within 30 seconds)
    ↓
[Language detection: Arabic or English based on greeting or locale]
    ↓
Short Intake Flow
  → "Hi! Sorry we missed your call. I can help you book.
      What's your name and what are you looking for?"
    ↓
Patient Replies
  → Bot gathers: name, concern, preferred time
    ↓
[Decision Gate]
  → Simple booking request → Send Cal.com link or manual booking request
  → FAQ (hours, location, how to book) → Auto-answer
  → Clinical / complex / pricing / insurance → Human handoff
    ↓
Confirmation + Logging
  → Confirm appointment or handoff to staff
  → Log to Google Sheets: lead, channel, language, outcome, timestamp
    ↓
Staff Alert
  → WhatsApp or email alert to clinic owner/manager with summary
```

### 4.2 · Behavior Rules

| Scenario | System Behavior |
|----------|----------------|
| **Missed call — business hours** | WhatsApp within 30 seconds. Tone: "Sorry we missed you! Let me help." |
| **Missed call — after hours** | WhatsApp within 30 seconds. Tone: "We're closed now, but I can book you for tomorrow. What works?" |
| **Patient sends voice note** | "I'd love to help! Our booking assistant works best with text. Could you type your question? 😊" |
| **Patient asks clinical question** | Immediate handoff: "Great question — let me connect you with the clinic team for the right answer." |
| **Patient is angry or urgent** | Escalation: "I understand this is urgent. Let me get a team member to help you right away." |
| **Bot can't understand message** | "I want to make sure I help you correctly — could you rephrase that?" + handoff after 2 unclear rounds. |
| **Patient wants to cancel** | Direct handoff to staff. Never auto-cancel. |
| **Duplicate caller** | Recognize returning number: "Welcome back! How can I help this time?" |
| **Conversation timeout** | If no reply for 2 hours during business hours: "Just checking in — would you still like to book?" One follow-up only. |
| **Double booking risk** | Check availability before confirming any time slot. |

### 4.3 · Language Handling

- Default first message: **bilingual** (Arabic + English in same message)
- Patient's reply language → all subsequent messages match that language
- If unclear → continue bilingual until signal received
- Tone: warm, professional, human-sounding — never robotic

**Example first message (bilingual):**
> 🇦🇪 مرحباً! لاحظنا أنك اتصلت — كيف يمكننا مساعدتك في حجز موعد؟
>
> 🇬🇧 Hi! We noticed you called — how can we help you book an appointment?

### 4.4 · Patient-Side Experience Principles

- Feels like **texting a helpful clinic assistant**, not a bot
- **No menus**, no numbered options, no "press 1 for..."
- **Conversational flow** — the bot asks one question at a time
- **Fast** — first message arrives before the patient considers calling another clinic
- **Graceful exits** — any confusion → human handoff, never loops

### 4.5 · Clinic-Side Experience

- **Zero training required.** Owner gets: staff alert when handoff needed + weekly report.
- **No new software to learn.** Alerts via WhatsApp or email. Reports via a shared Google Sheet or simple PDF.
- **Onboarding call: 30 minutes max.** We say: *"Give me your clinic number, your working hours, your location, and your booking preferences. We handle the rest."*
- **Weekly summary:** Call-by-call breakdown. Recovered patients. Conversion rate. Delivered as a clean 1-page sheet.

### 4.6 · V1 Non-Goals

❌ Clinical advice or treatment explanations
❌ PMS / EHR integration
❌ Custom dashboard
❌ Voice call handling
❌ Insurance quoting
❌ Multi-specialty (dentistry only)

These are Growth/Scale tier capabilities, not V1.

### 4.7 · Success Metrics

| Metric | Target |
|--------|--------|
| Time to first response | < 30 seconds |
| Patient reply rate | > 40% |
| Booking conversion (from replied) | > 25% |
| Recovered bookings per week per clinic | ≥ 3 |
| Cost per recovered booking | < 15 AED |
| First pilot closed | Within 14 days |

### 5.2 · Tool Guidelines

**Codex:**
- Use for ALL implementation work
- Keep code modular: separate webhook handler, message logic, booking logic, logging
- Deploy on Render with environment variables for API keys
- Test thoroughly on your own number before any pilot

**Manus (expires in ~7 days — prioritize):**
1. **Day 1 task:** Scrape 100 Gulf dental clinics across Dubai, Abu Dhabi, Sharjah, Riyadh, Jeddah
2. **Data per clinic:** Name, phone, WhatsApp (if visible), Instagram, website, Google review count, any reviews mentioning phone/response issues
3. **Day 2 task:** Shortlist 30 best-fit clinics (match ICP), write 1 personalized outreach angle per clinic
4. **Day 2-3 task:** Map Gulf dental AI competitors — who supports Arabic? Who targets Gulf? What's their pricing?
5. **Day 3 task:** Draft 3 outreach messages per top 20 clinics (WhatsApp, Instagram DM, email)
6. **Do NOT** use Manus for coding, product design, or anything Codex handles better

**Twilio WhatsApp:**
- Apply for WhatsApp Business API access **immediately** — approval can take 1-7 days
- Use a message template for the first outbound message (Meta requires this)
- Pre-approve template text: keep it short, professional, no marketing language
- Cost: ~$0.005/message + Meta template fees — negligible for MVP
- Test with your own number first

> [!WARNING]
> **WhatsApp Business API approval is a potential blocker.** Apply on Day 1. If approval delays beyond Day 5, use a sandbox number for the pilot demo and deploy on production number once approved.

**Cal.com:**
- Free plan is sufficient for MVP
- Set up a booking page per pilot clinic with available time slots
- If the clinic has an existing booking system they prefer, use manual booking request (bot collects info → staff books manually)

**Google Sheets:**
- One sheet per clinic: columns = timestamp, patient number, language, concern, outcome, booking status, notes
- Weekly summary tab with key metrics
- Share read-only with clinic owner

### 7.6 · Call Close Script (10 Minutes)

**Minutes 2-4 — Ask about their pain:**
> *"How does your clinic handle missed calls right now? Do you have a system for that, or does it kind of fall through the cracks?"*
*(Let them talk. Listen. Mirror their pain back.)*

**Minutes 4-6 — Show the demo:**
> *"Let me show you exactly what Jawab does — it takes 60 seconds."*
*(Share screen or send link. Walk through: missed call → WhatsApp → booking.)*

**Minutes 6-8 — Tie to their situation:**
> *"Based on what you told me, if Jawab catches even [X] of those missed calls per week, that's [Y] patients your clinic is recovering that would have gone elsewhere."*

**Minutes 8-10 — Offer the pilot:**
> *"Here's what I'd suggest: let me run it on your number for 7 days — completely free. At the end, I'll send you a report showing exactly how many patients we recovered. If the number is zero, we shake hands and move on. If it works, we talk about a simple monthly plan. Fair?"*

## 10 · MISSING POINTS & PATCHED HOLES

### 10.1 · Critical Items Found and Patched

| Issue | Status | Patch |
|-------|--------|-------|
| **WhatsApp Business API approval delay** | 🔴 Critical | Apply Day 1. If delayed, use Twilio sandbox for demo, deploy on production number once approved. Have a backup demo using screen recording of the sandbox. |
| **Data privacy (Gulf regulations)** | 🟡 Important | UAE has Federal Decree-Law No. 45/2021 on personal data protection. Saudi has PDPL. For V1: state in onboarding that patient data is stored securely, not shared, used only for booking. Add a brief privacy note to the first WhatsApp message: "Your information is used only for booking purposes." Build proper privacy policy before scaling. |
| **Payment collection method** | 🟡 Important | Gulf B2B standard = bank transfer. Set up a UAE or Saudi bank account or use Wise Business for receiving AED. Invoice via Google Docs template or a simple invoicing tool. Stripe works for international but adds friction in Gulf. |
| **Clinic onboarding SOP** | 🟡 Important | Create a 30-minute onboarding checklist: clinic name, number, hours (weekday + weekend), location link, staff alert contacts, booking method preference (Cal.com link vs manual), any specific greeting preference, any FAQ to pre-load (parking, insurance accepted, etc.). |
| **Multi-number handling** | 🟢 Later | V1 = one number per clinic. Track as separate Twilio numbers. Multi-number routing is a Growth tier feature. |
| **Legal structure** | 🟡 Important | For Gulf B2B: operate as a freelancer/sole proprietor initially. If you're based in Egypt, you can invoice Gulf clinics internationally. Consider a UAE freelance visa or free zone company later if volume justifies it. Don't let legal structure block Day 1. |
| **Conversation handoff quality** | 🟡 Important | When handing off to staff, send the full context: patient name, language, concern, conversation so far. Staff should never ask the patient to repeat themselves. |
| **System downtime / errors** | 🟡 Important | Set up basic uptime monitoring (UptimeRobot, free tier). If the system goes down, have a fallback: Twilio sends a simpler pre-written message: "Thanks for calling [Clinic]. We'll call you back shortly." Log the failure. |
